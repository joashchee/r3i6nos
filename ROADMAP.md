## 7. Phase 6: slim and release

- [ ] **A mainline kernel instead of the vendor 4.4.189: estimated 2026-11-11, not decided** (`docs/MAINLINE-KERNEL.md`). ROCKNIX (officially, "Mainline Linux", libmali or Panfrost) and Arch R (6.12 LTS, Mesa Panfrost) already run the genuine R36S on one. **About 40-75 working days in all (8 to 15 weeks of focused work; calendar time is longer because panel variants need testers); a first slice that boots our image to the menu on the one unit, with graphics, sound, buttons and a battery reading, is about 20-30 days.** It would also shrink rule 2 to the bootloader and the card's panel data, make `r3i6nos-setup` take seconds, and unblock Debian 13 and later. Biggest risks: panel and board revisions (we own one unit), Panfrost against the Mali blob, and re-measuring audio, input, battery and hot-plug. **Order: trials T1-T5 first, then the half-day spike (boot ROCKNIX's RK3326 image on the unit and read its kernel config, DTS and patches), then decide.**
- [ ] **Debian 13 (trixie) instead of 12 (bookworm): evaluated 2026-11-11, decision: stay on 12 for now.** Measured with a native arm64 `debootstrap` of the same package list: **663 MiB vs 664 MiB** unpacked (228 vs 240 packages), so size is no reason either way. Trixie has systemd 257.13, glibc 2.41 (its minimum-kernel tag is 3.7.0: fine with 4.4), SDL 2.32.4 (bookworm 2.26.5), Python 3.13.5 (nothing we import was removed: scanned), LuaJIT 2.1.0+openresty20250117 (bookworm 2.1.0~beta3), OpenSSH 10.0. **The one real risk is systemd on the 4.4.189 kernel:** upstream says kernels below 5.4 get "limited testing" and an `old-kernel` taint (v257), cgroup v1 is "obsolete" and **ignored unless `SYSTEMD_CGROUP_ENABLE_LEGACY_FORCE=1` is on the kernel command line** (v256/v257 NEWS), and v258 makes 5.4 the minimum and drops cgroup v1; the stock kernel does contain a `cgroup2` filesystem (seen in the captured `Image`), so v2 may mount, but nobody has booted it. So trixie is the **last** Debian whose systemd even tries a 4.4 kernel, and it buys little: bookworm is in LTS to 2028-06-30 (regular security ended 2026-07-11), trixie has regular security to 2028-08-09. **Cost of the move:** package renames (`libasound2` to `libasound2t64`, `libmpg123-0` to `libmpg123-0t64`; found by the test build), both LÖVE runtimes rebuilt in trixie containers (and 12.0's JIT retested on the new LuaJIT), SDL 2.32's KMSDRM behaviour retested (the present-once black first frame, the pad mapping), the ports' link check against trixie's packages, and every `Debian 12` in the docs; apps built in Debian 12 containers still run on 13 (glibc is forward compatible). **Do it only as an experiment after the T1-T5 hardware trials pass** (`docs/TRIAL-T1.md`): `SUITE=trixie` plus the two names on a branch, a CI image, a carrier boot, and read the boot report (systemd starts with cgroup v2 or needs the force flag, no failed units, the LÖVE menu draws, memory and boot time against bookworm's). The real answer to the old kernel is a mainline kernel (ROCKNIX and UnofficialOS run mainline with panfrost on RK3326), a much bigger project that would also change rule 2's blob story: not scheduled.
